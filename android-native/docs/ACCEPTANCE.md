# 原生客户端验收限制与验证清单

记录日期：2026-10-20。本文件定义证据的适用范围及后续验收步骤。当前源码版本为 `0.2.4-preview`（versionCode `6`）；最新构建、测试数量、签名、SHA-256、来源提交和 dirty 标志统一以 [VERIFICATION.md](../VERIFICATION.md) 为准。

## 证据可以说明什么

| 证据 | 可说明的范围 | 不可据此推导 |
|---|---|---|
| Kotlin/Java 编译、单元测试、Lint、APK 构建 | 指定提交、来源工作树和变体的可构建性、静态检查及实际运行测试 | 所有业务完整验收；未测试设备或渠道已经通过 |
| 专用 Workspace 与现有后端路径 | 原生业务入口已实现，对接既有账号、项目、权限、版本和生命周期体系；通用 API 操作表单不再作为业务导航 | 真实账号、外部服务、付费模型或生产部署可用 |
| MockWebServer 与原生 UI fixture | 隔离账号和本机接口下，已测页面的真实 Compose 操作与请求字段、固定版本、草稿恢复和冲突行为 | 已访问生产；真实权限、邮件、模型、DSH、语音或推送端到端成功 |
| **历史 `0.1` 基线：API 33 / 37 各 `OK (20 tests)`** | 当时两台模拟器的 6 个仓库、5 个业务 UI、5 个文档解析、2 个导出、1 个扫描页渲染和 1 个播放控制用例 | `0.2` 当前完整套件已经通过，或这些历史结果覆盖本轮新增工作区 |
| 本轮 API 33 / 37 完整套件 | 以最新验证报告明确列出的最终测试、失败修复及复跑范围为证据 | 将正在运行、只编译或未执行的测试预记为通过 |
| 原生截图/层级与 APK DEX 扫描 | 所抽查屏幕和对应安装包的 WebView 类引用情况，按实际应用与构建归因 | 一张截图证明所有交互；未扫描的新 APK 沿用旧包结果 |
| PDF、Office、版本与导出样本 | 指定文件的提取、位置、警告、固定版本、尺寸限制和导出行为 | 所有扫描件、版式、公式、图表和真实资料均正确 |
| 扫描页 prepare 检查 | 图片上传/登记与模型执行分离，明确 `analyze:false` 并拒绝意外任务 | OCR 已成功；没有存储/传输消耗；旧 `/page-images` 也不会调用模型 |

早期失败和修复记录应保留为历史，但不得作为当前版本的通过或失败结论。响应正文 IO、账户隔离、修订冲突、固定引用和草稿恢复等回归应在本轮集成版本重新验证。测试中用随机账号/项目隔离真实本机草稿，不删除用户草稿来制造通过。

## 尚待完成的外部与实机验收

- **真实生产授权**：2026-10-19 已经用户授权完成备份、0078–0080 迁移与两端部署。事务创建、授权页可达已核对；自动验收停在需人工完成的 Turnstile，未发送密码登录请求。仍需以真实业务账号完成系统浏览器授权、回调、退出撤销、角色切换和线上数据读写，不能将路由上线视为登录整链成功。
- **真实模型、OCR 与实时语音**：需独立验证模型路由、供应商异常、计费、转录、扫描识别、长运行和真实语音连接。不得为补齐报告自动调用付费模型；协议或模拟结果不能替代服务连通证据。
- **FCM 配置与实际投递**：Firebase 公共应用配置、服务端私钥和部署状态需要核对。需验证在线、后台、杀进程、令牌轮换、退出/换号、重复消息和撤权。无 Google 服务的补查不能承诺即时送达。
- **DSH 与其他外部流程**：实际设备配对、目录绑定、审批/输入、断连恢复、成果上传与人工采纳，以及恢复邮箱邮件、支持工单和管理权限的真实交互需要端到端验收。
- **四小时物理录制**：需完成真实手机四小时音频/视频、锁屏、暂停恢复、来电、进程终止、低电量、存储不足和片段上传，并保留人工听看结果。模拟器不能替代这些结论。
- **可比 Release 资源负载**：需在同设备、同数据、同认证状态与同场景下比较最终 Release。计入可归属的关联进程与 WebView 渲染进程；模拟器未登录页不能证明项目业务负载更省内存或电量。
- **完整业务与设备覆盖**：专用工作区、格式/块/表格、标准评分人工修正、任务依赖、创建澄清、AI 采纳、人员隐私和帮助入口已写入本轮代码。仍需核对真实权限竞争、跨设备协作、手机/平板布局、字体放大、键盘、无障碍和长文/大列表表现；不能用代码存在或 API 数量替代验证。

## 后续验收步骤

1. **固定版本与环境**：记录合并到 `main` 的提交、受跟踪源文件 dirty 状态、`0.2.4-preview` / code `6`、构建变体、API、设备、签名来源与 APK SHA-256。核对构建脚本从实际版本生成的文件名；保留旧应用和用户未同步数据。
2. **静态与自动化**：运行契约/类型校验、单元测试、Lint、后端与 Web 相关回归、原生构建和完整 instrumentation。报告实际通过/失败/未运行数量；若仅单项复跑，不写成完整套件复跑。
3. **授权与权限**：验证 PKCE 取消、过期、重放、错误 verifier；负责人、组员、管理员、被移除成员、换号及匿名公开资料边界。账户/项目变化后不得继续访问上一个身份的文件或麦克风。
4. **创建与协作**：验证草稿附件、澄清、固定预览提交；任务领取/分工/依赖/提交/验收/重开与邀请；DSH 成果复核；标准变化、人工分数修正和历史追问。费用或结果不确定时必须保留输入并显式确认，不自动重复写入。
5. **资料与本机恢复**：用文本/扫描 PDF、DOCX、XLSX、PPTX、音视频和长文核对正文、位置、警告、固定版本对比和原文引用。验证贡献者、归档/回收恢复、续传、低存储、草稿跨进程恢复及人工处理 409；首次离线深链接单独测试。
6. **扫描页与费用隔离**：确认 prepare 无模型任务，缺少新接口时停止；验证来源生命周期变化、撤权、重复登记和异常重试。空白确认不调用模型，OCR/总结/媒体回退需另行确认并独立记录结果。
7. **UI 与设备**：核对手机/平板、主题、字体、键盘和无障碍；重要导航无需横向滚动。实测录制、外设、后台、语音、推送、恢复邮箱、工单图片和分享目标。
8. **资源测量**：使用启用 R8 的 Release，核对实际 Baseline Profile 是否打包。冷启动、PSS、CPU、滚动帧和 APK 体积按场景保留原始样本，报告中位数与波动；不可读取或不可比项标记未知，不推测替代。

## 发布与完成判定

代码合并、远端推送、测试部署、生产迁移和应用商店发布是独立操作。文档与安装包准备不构成部署授权，测试中也不应自动执行生产写入。

当前可以分别交付专用原生客户端代码、安装包及其可复现证据。是否满足“全部功能迁移并与现有后端对接”需逐项核对最终矩阵、自动化及真实外部验收；真实生产授权、FCM、模型/语音、四小时录制及可比资源负载等仍未闭环时，不宣称全目标完成。
