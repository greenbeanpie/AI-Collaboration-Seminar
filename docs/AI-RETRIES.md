# AI 自动恢复与管理员批量重试

调用内的供应商回退和 JSON 修复保持原规则。业务作业因 `AI_UNAVAILABLE`、`AI_OUTPUT_INVALID` 或评价生成失败而失败后，D1 同一事务保存失败状态和自动恢复意图；一分钟 cron 在失败至少 60 秒后排队新的请求。cron 调度存在延迟，因此不是精确到秒的定时器。同一链最多追加 3 次；每次业务请求仍使用原有调用内回退，连续 3 次恢复失败后停止。成功不会继续排队，等待用户输入不视为失败。

执行窗口管控的运行（AI 分片、草稿预览、OCR 批次）采用不同的恢复语义：结构化输出无效时不走上述失败自动重试，而是把逻辑请求置为 `waiting_input`，`execution.pauseReason` 记为 `output_invalid`（其他取值还有 `round_limit`、`request_uncertain`、`interrupted`），已保存的检查点和已付费的成功页/片段保留，后续恢复续跑时不重放已付费请求。恢复途径是用户在界面显式继续，或执行分片由队列/分钟级 cron 从 D1 待处理行派发；这类暂停不算失败，不进入失败统计与管理员批量重试队列。

旧失败作业保持终态。新作业通过重试映射关联原请求，并原子替换当前业务指针。页面查询旧作业 ID 时跟随后继；尚有恢复计划的逻辑请求返回 `queued`，保留失败错误，并提供 `retry.status/attempts/nextAttemptAt/originalJobId`。D1 内的原失败状态和 token 用量记录不会抹除。

## 管理员操作

“设置 → 系统概况 → 失败 AI 请求重试”显示当前失败请求数。管理员可以查看；超级管理员或已有运维令牌可以点击“将所有失败请求排队重试”。该操作快照当前失败业务作业和活动草稿预览，保存批次，再由 cron 分批消费；不在 HTTP 请求中立即调用模型。重复点击和网络重试使用同一幂等键，不重复创建批次。超级管理员也可在系统概况查看和一键清空 AI 调用日志；日志只保留调用状态、阶段、耗时、脱敏的错误原因与请求目标元数据，不包含提示词、模型回答或密钥。

已取消、已被替代、输入/标准/配置/权限失效的项目会跳过并显示原因；等待项目并发槽位的项保持排队，不消耗模型恢复次数。一个批次排队完成不表示模型已成功。管理员再次点击可为已经停止的有效失败请求开启新一轮最多三次的自动恢复；已成功创建后继的历史失败项不会再次消费。配置或权限修复后，先前跳过的项可以在新批次重新检查。

- `GET /api/v1/admin/ai-retries`：汇总失败数、活动/最近批次、已排队/待处理/跳过数量及原因，不返回提示词或供应商密钥。
- `POST /api/v1/admin/ai-retries`：提交 `{ idempotencyKey: UUID }`，返回 202、批次和是否复用了既有批次。
- `DELETE /api/v1/admin/ai-retries`：仅超级管理员可调用；原子删除尚未领取的 `pending` 重试队列项，并关闭已无待处理项的批次。正在执行、已排队、已跳过的条目、失败源作业及 AI 诊断日志均保留。领取与清除竞争时，以数据库中先成功的状态更新为准，不会中止已开始的调用。
- 模型诊断探测是独立管理员诊断，不属于可恢复的业务作业；不把旧诊断日志当作新的用户请求重放。

## 恢复边界

每次重试重新检查原请求账户、项目成员权限、当前业务指针、来源生命周期、任务/标准版本和冻结模型配置。源总结与音频处理保留可复用的成功阶段；Whisper 转录、已检查块、已完成摘要及媒体窗口不必全量重做。草稿预览保留工具输出和已完成读取，只替换尚未确认的请求或无效最终输出。新语音答辩已接入，文件转录仅 Whisper、实时转录经 Gateway，TTS 使用系统本地语音，不创建云端作业；真实模型仍需专用凭据验收，见 [语音说明](GEMINI-VOICE-PLAN.md)。

迁移 0056/0057 新增批次、条目、后继映射和自动重试队列。部署先记录 D1 恢复点，再应用迁移、部署后端和前端。数据库含 FTS5 时 D1 SQL export 不可用，使用当前 Time Travel 书签保留迁移前恢复点；恢复数据库需另行确认，不能自动覆盖线上写入。

验证包括三次停止、一分钟到期、后继追踪、取消/撤权、并发单次入队、跨批次重试、事务回滚，以及 Chromium 桌面/手机管理界面。可复现界面检查：启动前端开发服务器后，设置 `UI_ORIGIN`，运行 `node scripts/verify-admin-ai-retries-ui.cjs`；所有 API 使用本地 fixture，不产生模型费用。
