## 工作方式

项目围绕一个主目标组织。任务页统一维护子任务、前置依赖、认领、分工、成果提交和验收。依赖用于表达顺序和提示当前缺少的前置成果，允许提前执行、提交和人工验收；它不会自动把任务改成阻塞状态。

评分页统一维护项目要求和评分标准，并保存每次材料检查、答辩演练的独立记录。非评分要求仍是检查项。确认后的标准及每轮使用的目标、成果和回答版本固定下来，后来修改不会改变历史。各轮结果不合并成最终成绩。

资料页提供背景、参考、成果的统一列表和详情。来源原文、文件、页码、引用与成果文档仍保留原有版本身份；用途标签不改变证据类型。背景文档可以编辑和查看历史。旧链接仍能定位到对应来源、文档或记录。

个人资料在账户级维护。专业、技能与特长、倾向职位和每周总可用时间不再按项目重复填写。旧项目中的个人信息成为仅本人可见的导入候选，本人选择字段并核对后保存。导入专业或技能不会自动公开或扩大 AI 授权；每周可用时间仅本人可见。

## 数据与兼容

- 主目标独立于任务，不参与任务计数和工时。旧任务、父任务分组、提交轮次、完成状态和引用 ID 保留。
- 依赖图采用独立版本检查，并验证同项目引用、自依赖和环；并发依赖修改不会通过竞态形成环。
- 要求和评分版本组成已确认标准，数字评分使用完整维度及服务器加权计算。证据不足、未读附件或输入超限必须显示真实限制。
- 来源和成果保持各自的正文、版本、权限、回收站及并发控制。统一资料库与账本中的第三方资源声明是两个独立接口。
- 个人信息先复制到用户级候选，再清空项目旧字段；用户、成员及项目关联保留。全局资料及原有隐私设置不被自动覆盖。
- 项目导出包括主目标、资料用途和版本、任务依赖、标准、提交及评分历史，不包括用户级私密资料或导入候选。

本轮按用户追加指令发布现有 Cloudflare 生产资源，不调用付费真实模型。固定模型响应验证接口、证据和状态处理，不能证明真实模型的评价质量。
