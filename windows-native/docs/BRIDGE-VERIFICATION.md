# Windows Bridge 源码补齐记录

本记录对应后续 0.1.1 源码，不属于 0.1.0 实测安装包。没有连接真实 DSH、调用模型、部署服务或执行 GUI 自动化。

## 已实现

- 账户页设备项目授权调整、授权变化预读核对和显式舍弃本机勾选；保留设备撤销入口。
- 任务页专用代实施工作区：适用性、已授权且绑定项目目录的设备、交接历史、明确派发、取消、成果说明/文件、人工采纳提交。审批/补充输入在 DSH 完成，不伪造浏览器端审批协议。
- 所有关键读取强制联网；派发前复查当前任务、适用性、设备及未结束交接。采纳前再读任务和成果；核对指纹包含交接、更新时间、任务版本和成果内容，任一变化都撤销人工核对。
- Bridge 在线请求先落盘再发送，账户隔离并保存固定参数/幂等键。响应丢失、取消、408/429/5xx 等保留未知结果；普通按钮不能重复派发。只读核对必须与原设备/任务/版本一致；取消/采纳必须有服务端完成证据。
- 人工恢复需再次确认；以原参数和原请求标识重试，且同一请求不能并发发送。适用性接口没有支付去重承诺，界面明确提示可能再次产生模型费用。没有后台自动重放。
- 仅在当前可见页面存在进行中状态时轮询；页面卸载停止计时器，托盘不请求状态。

## 验证

- Core 回归 **38/38** 通过，其中新增 11 组覆盖上述持久请求、账户切换、未知结果核对、人工重试标识/参数保持、并发重试阻断、版本/成果变化、设备约束与非法字段/敏感字段拒绝。
- 现有后端 Bridge/设备设置/任务适用性及批量适用性四个测试文件 **63/63** 通过，使用本机测试环境。
- WinUI Release x64 构建 **0 警告、0 错误**。日志为 `windows-native/artifacts/verification/bridge-*.log`，合入 main 后另行复验。

## 限制

尚未执行真实角色及设备、结果文件全流程、原生键盘/无障碍/缩放和真实网络断线验收。项目授权 API 没有原子 expected-version 条件；当前预读检查能阻止已观察到的旧授权覆盖，无法消除读取后提交前的服务端并发窗口。任务级 CAS/生命周期权限仍由既有服务端负责。

此持久在线协议目前仅用于 Bridge 四类明确操作；其他普通在线业务尚未全面接入。0.1.0 的资源报告不能推断新增源码的占用；尚未发布新的安装包或更新清单。
