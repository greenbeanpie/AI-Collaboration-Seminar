# 任务成果文件专用迁移记录

对应 0.1.2 源码。源码实现与本机 mock/协议检查不代表真实角色、原生 GUI、实际长时间传输或自动处理验收完成。

## 操作与协议

- 任务详情新增成果文件管理页，分页读取当前及归档记录，预览/保存原文件，查看材料正文及不可变版本历史，归档/恢复材料。文件自身归档、回收仍在附件管理中处理；界面明确两种生命周期不同。
- 当前执行人或资料管理权限成员可上传新文件；替换操作使用所选材料的 revision，提交 `PUT .../tasks/{taskId}/files/{materialId}`，不能误用任务 revision。旧文件、旧材料版本及旧提交引用保留。
- 原文件先复制到当前账户私有目录，绑定 SHA-256；上传沿用已有分片传输。登记前在当前账户 SQLite 保存原 fileId、固定文本、材料 revision、私有副本路径及摘要。取消、重启或上传 journal 写入失败后仍有恢复依据。
- Office 可选择提取 DOCX/XLSX/PPTX 正文；最多 60,000 UTF-16 字符，超限在界面及正文明确标记截断，保留代理对边界，原文件完整保留。任务材料正文不额外创建无关项目来源。
- 登记请求保存 `waiting_upload` / `sending` / `unknown` 状态，不进入普通后台同步。响应须证明同一 taskId、fileId、materialId、versionId 和有效材料 revision，才确认完成。失败或结果不明只保留记录，不自动新上传或静默重放。
- 恢复前按原 fileId 查询文件库状态。`available` 不重复上传；`pending` 校验私有副本摘要后沿用原上传。记录在当前任务文件中的完成证明通过 GET 分页核对；若其他客户端已再次替换，保留记录并提示人工核对材料历史。
- 人工恢复登记要求明确确认可能的自动处理费用，沿用原 fileId、原 body 与原请求键。当前服务端主要依赖 fileId → material 的自然去重，不把它表述为额外的付费模型幂等保证。人工停止恢复只标记记录，不删除文件、材料或历史，不代表撤回服务端动作。
- 账户替换会取消旧账户的传输令牌，上传/下载与账户令牌关联；迟到登记响应不能确认另一个账户的本机请求。

## 未验收和明确限制

- 新任务文件登记的 fileId 分配响应如果丢失，仍需人工核对项目附件库；不能从未知响应推断成功。私有原文件副本保留。与全局在线意图迁移一致，这个分配步骤尚非完整持久化在线事务协议。
- 本机读取当前任务文件只能自动确认仍为当前版本的登记；跨客户端再次替换后的历史证明须人工核对，不依据“当前没找到”自动重发或清除。
- Office 正文提供内容而不保证原文版式；PDF/图片的扫描补页/OCR 不是本次实现。服务器自动处理由原项目策略决定，未经真实模型验证。
- 原生文件选择器、权限角色、离线重启、低磁盘/磁盘写入失败、真实上传中断/设备切换及界面缩放/无障碍仍待验收。用户停止 GUI 自动化后没有继续操作界面。
- 任务 AI 拆解/分工建议、辅助计划和手动 Agent 上下文导出仍未完整覆盖；不把任务文件完成功能扩大为整个任务协作迁移完成。
