## 草稿与退出的具体边界

- 已接入自动本机持久化的范围：任务编辑/提交说明、资料 intake、富文档、项目聊天、简单创建字段、AI 创建 payload/人工预览、个人资料、昵称，以及项目基本信息/主目标/协作规则、标准维度、人工评分/追问、团队权限/邀请申请、评论/问询/回复、管理员非密钥模型/音频/路由配置、通知偏好及支持回复；保留原始 `expectedRevision`/`expectedGraphRevision`/`permissionsRevision`/配置 `expectedVersion` 和必要原报告，避免恢复时静默基于新版本覆盖。
- `SaveBeforeCloseAsync()` 等待当前草稿写入，保存失败返回 false；账户切换会失效旧页面回调；密码/API Key/Gateway Token 输入不进入本机草稿并阻止未清空时关闭。
- 多分区表单按手工声明的类型化控件分别保存；标准/评分以原始标准或报告快照作基线。提交期间继续输入的草稿不随成功响应清除；恢复时已经不存在的选择项保持未选择，避免静默改为其他成员。
- **全局无丢失验收尚未完成**：上述源码覆盖仍需模拟存储失败、应用重启、同账户重新登录和并发编辑验证；部分次级表单（例如 Bridge 配对文本、演练参考选择及未覆盖流程）尚未纳入统一自动恢复。不能把 `HasUnsavedChanges` 当前覆盖范围扩大为整个客户端。
- Core 离线队列提供稳定键；Bridge 四类在线操作另有账户隔离的持久请求记录及人工恢复协议，详见 `BRIDGE-VERIFICATION.md`。普通在线 `SendAsync` 每次调用仍生成新键，其他付费流程尚非完整的持久化在线意图协议。UI 不静默自动重试付费操作。
- 富文档恢复保留原 revision；保存冲突时保留草稿。未知或缺少合法 doc 的版本禁止以空文档覆盖。工单创建状态不明须人工核对后才能解锁再次提交。

## 验收优先顺序

1. 使用本机模拟服务核对真实 DTO、错误、分页重复游标、跨账户迟到响应及上述深链接；检查虚拟化列表只创建可见范围控件。
2. 用测试角色验证任务提交/人工验收、富文档未知节点往返、标准/人工分数保留、成员权限拒绝、撤权和 409；不在生产数据上探索。
3. Office mock 覆盖初始化/批次/complete 的 exact body、超出 bounds、UTF-16 surrogate 边界、相同输入恢复、缺 journal digest replay、来源生命周期变化、账户变化与中断 partial；验证未调用 analyze/OCR/model。
4. 补全表中未覆盖流程后，开展真实授权端到端及原生设备验收。截图/采样只证明实际执行过的场景；完整性能三轮及升级验证按主矩阵保留原始证据。
